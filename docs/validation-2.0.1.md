This change is prepared for a draft PR. No Obsidian desktop session is available in this environment. Browser results below use real plugin modules and CodeMirror with a minimal Obsidian DOM/workspace adapter; they do not establish that the reported Windows/Minimal/Style Settings runtime behavior is resolved.

## Causes located before editing

The initial regression runner was executed against the 2.0.0 source at `0e8b79862f532dfefeb2887eeff0cdf843d0a2bc`. Seven of eight scenarios failed; the [initial result and console stack](evidence/2.0.0-regressions.json) are preserved. The unchanged legacy browser suite did not cover these lifecycle conditions.

| Report | Diagnosis / reproduction | Change |
| --- | --- | --- |
| Frozen breadcrumb; later breadcrumbs cannot open | Editing with an open popup invokes `dismiss()` from `ViewPlugin.update`. Its highlight cleanup dispatches another CodeMirror transaction during the current update. CodeMirror reports `Calls to EditorView.update are not allowed while an update is in progress` and drops the crashed view plugin. Popup state was nulled before DOM cleanup, stranding a nonfunctional dialog. | Remove the dialog and observers first. Skip editor dispatch from update/destroy callbacks; clear reconfiguration highlights after the transaction. Document edits already clear the highlight state field. |
| Popup does not time out after a rendered-row click | An additional reproduction found that ordinary mouse focus in Reading mode satisfied the unconditional focus guard forever. | Only keyboard focus protects against timeout. Pointer interaction restores normal dismissal. Detached embed targets also dispose their popup. |
| Embed guides disappear | Replacing host contents removes the SVG, but the old surface keeps drawing into that detached SVG. A postprocessed section mounted after the queued scan is never discovered without another layout event. Both conditions fail in browser reproductions. | Observe actual surface mounting/removal/replacement and reattach the overlay. Use a coherent DOM fallback during partial registration. |
| Outer-document scrolling becomes expensive | The old document scroll listener schedules every surface; each frame recollects the hierarchy, measures markers, and replaces SVG paths. Five unchanged scroll events caused five overlay rewrites. Source inspection also found whole-subtree cloning for every DOM-fallback parent. This establishes unnecessary work, not the precise timing or complete cause of the user's application freeze. | Cache content-relative measurements, invalidate affected surfaces on real layout/content changes, avoid global postprocessor invalidation, and prune nested subtrees while reading fallback labels. | Breadcrumb Threading toggle ineffective | The standalone 2.0.0 fixture already draws visible threads with the toggle on and main threading off. Its exact independent failure was not reproduced. A 150% path was identical to 100%. | Initially remove the geometry ceiling (the overshoot this introduced is corrected in the 3141a66 follow-up below); expose a 0–500% slider and an unbounded nonnegative finite precise field. Expand the native range and recover the saved CSS value on control reconstruction. |

## Follow-up to draft commit 943dcfb

The user's later reports exposed a gap in the earlier browser adapter. Obsidian 1.13.7's `enhance.js` passes a string `cls` to `classList.add` as one token for SVG creation. Our adapter used `setAttribute`, incorrectly accepting space-separated strings. Inspection of the [official 1.13.7 runtime](https://github.com/obsidianmd/obsidian-releases/releases/tag/v1.13.7) located this difference. With the corrected adapter, both main embed threading and marked-item breadcrumb threading throw `InvalidCharacterError` on 943dcfb. This supersedes the earlier conclusion that the independent toggle failure could not be reproduced. Inspecting the runtime helper is not running the plugin inside Obsidian.

The [943dcfb evidence](evidence/943dcfb-regressions.json) records the exceptions, wrapped-head failure, and marker measurements made before editing the responsible code. It also labels an initial scroll assertion as invalid: wheeling *inside* an independently scrollable embed correctly moved the inner scroller rather than the outer editor. That assertion is not evidence of a freeze.

| Report / remaining risk | Located cause or observed evidence | Follow-up change |
| --- | --- | --- |
| Embed threading absent; Breadcrumb Threading disables marked-item activation | Both shared SVG paths pass two classes in one string; the host helper throws. An unmarked head alone needs no thread path, explaining the different activation behavior. | Pass SVG classes as arrays. Run every browser suite with the corrected helper semantics. |
| Wrapped unmarked breadcrumb head crossed by its first static connector | The static spine starts at the parent's **first** text-line center plus rise. Baseline starts at 24.5px while the head's label ends at 58.64px. | Use the full label bottom as the lower bound for the spine start; retain the short-label rise. |
| Certain numbered parent markers crossed at 110% height | Editor starts used marker rectangles; a numeral's text range and bullet's layout box have different heights. Scaling the entire wrapped parent-to-child distance could extend across the numeral. | Use the parent's own row bottom as the common reference, excluding nested lists. This proved incorrect and is superseded by the marker-bound follow-up below. Main default changes to 103%; breadcrumb default remains 100%. |
| Checkbox overlap in embeds | Marker lookup stops at the first `.list-bullet`, even when it is hidden before a visible task checkbox. The fallback endpoint was 111px while the checkbox began at 93px. | Prefer the visible own checkbox, skip hidden placeholders, and never use a marker from a descendant list/embed. |
| Stray connector left of a nested embed / marker misalignment | An embed-only item's fallback rectangle covers the entire block, putting the marker at its midpoint. Obsidian's bullet glyph is a pseudo-element on a zero-width box, which the old width check also discarded. | Measure the bullet glyph; anchor textless items to their first line; preserve scale. Nested, scaled LTR/RTL fixtures assert one connector per owned item and clearance from checkboxes/bullets. |
| Outer scroll stalls and distorted embedded layers | The recording shows the stall but does not expose its event/DOM state. The previous renderer inserts SVGs and preview highlights into live transclusion content; this permits widget observers and scrollable-overflow calculations to see drawing mutations. Exact Windows/Minimal freeze timing has **not** been reproduced. | Use external, pointer-transparent drawing layers clipped to the viewport and every scroll ancestor. Scrolling changes layer placement/viewBox only, with no path replacement or writes inside the embed. Position also tracks surrounding content changes. Real wheel input tests inner and outer scrolling, unchanged editor text/height, and zero writes to the embed after settling. |

New settings are independently persisted: **Unmarked List Head Hover Breadcrumb Activation** defaults on; full-item scope includes the head row and full-marker scope includes only its gutter. Neither depends on threading. Both scopes off leaves unmarked heads inactive. **Unmarked List Head Static Tree Indentation Guides** defaults off and is subordinate to the main static-guide toggle. The activation section is renamed **List Hover Breadcrumb Activation Scope**.

## Follow-up to draft commit 3141a66

The [3141a66 evidence](evidence/3141a66-thread-height.json) was captured before editing production geometry. Eight focused browser scenarios failed. The previous row-bottom approach was incorrect: it shortened connectors whenever parent text wrapped. For a bullet whose bottom was 77.59px, the cap started at 196.20px. A later-child case also reproduced overshoot: the cap started at 61.80px, above the parent's bullet top at 70.41px.

Two fixture problems had hidden the failure. First, assigning depth by `indent / 2` made a four-space child jump from depth 1 to depth 3, so it had no modeled parent. The fixture now assigns depth by actual nested indentation levels. Second, Live Preview used raw text markers rather than a zero-width bullet with a visible pseudo-element or a checkbox with a hidden bullet placeholder. The added widget fixtures represent those shapes. These are still test fixtures, not the running Obsidian app.

The replacement separates the percentage calculation from the marker boundary:

- Marked parent anchors use their marker bounds, independent of the full wrapped row. Editor and rendered lists share visible bullet/checkbox measurement; numeric editor markers use the first numeral text range rather than the marker's padded layout box.
- 100% leaves the configured marker gap. Values above 100% may reduce that gap, but the stroke cap stops at the parent's marker boundary. Selecting a distant child therefore cannot extrapolate through or above its parent. The input continues to accept values above 100% and above the slider range; the visible reach is bounded by the marker.
- This change covers active-item/all-branches editor paths and the shared Reading/embed/breadcrumb renderer. Unmarked heads still use their full label/row bottom. The wrapped-head **static** guide correction is retained.
- Earlier assertions that required a start below the entire wrapped row, or required the full 100% gap at 103%, have been replaced with actual marker-clearance and reach checks. The updated tests require both a nearby start and a cap that does not cross the marker.

## Follow-up to draft commit ce34c7a

The [ce34c7a measurements](evidence/ce34c7a-checkbox-geometry.json) were recorded before changing production code. All nine initial checkbox scenarios failed. The earlier task widget omitted the number for an ordered checkbox, so it could not expose the number being crossed. The widget now includes the visible numeral and a separate checkbox label.

Two distinct geometry errors were located:

- Both marker readers returned the checkbox immediately, discarding a preceding visible number. For a `1.` task in the editor fixture, the number began at 134.80 px while both connectors reached 161.70 px. For a `12.` task the endpoint reached 176.16 px. Static guides and threads therefore passed through the numeral before reaching the checkbox.
- Thread spines were derived from the child's leading edge minus gap and length. With the same parent bullet centered at 77 px, changing the hovered child from an unnumbered checkbox to a numbered checkbox moved the spine from 104.80 px to 148.16 px. The all-branches path averaged these mismatched positions instead of attaching beneath the parent.

The replacement separates the marker's **protected bounds** from its **primary anchor**. Protected bounds include the numeral and checkbox; the anchor uses the numeral's text range, the visible bullet glyph, or an unordered task's checkbox. Static/thread endpoints stop before the protected bounds. Thread spines attach under the primary parent anchor at the default length of 28 px; custom lengths adjust that attachment outward/inward, independently of child marker kind and gap. Static sibling spines stay outside the outermost marker edge. Rendered native decimal markers are measured with font metrics off-document and positioned from the list item's content edge, not from label text after the checkbox. Nothing is inserted into live embed content to measure them.

The main gap default is 6.5 px in Style Settings metadata, CSS, and runtime fallbacks. Breadcrumbs retain 4 px; saved overrides retain their values. Height defaults and the parent stroke-cap bound are retained. The expanded checkbox suite has 14 scenarios, including Source, RTL, scaled embeds, saved gap overrides, and the length control. Its initial nine failing cases are preserved above. The native `12.` embed fixture uses a blank line before that nested list so its source hierarchy is valid CommonMark; the initial measurement fixture lacked that blank line, but still reproduced the separate ordinal-overlap defect.
